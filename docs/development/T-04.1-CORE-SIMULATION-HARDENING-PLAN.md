### Confirmed code-review gaps to investigate and cover

1. **Snapshot depth validation:** `EventQueue.restore()` calls `validate()`, but `validate()` currently rejects only invalid integer/negative depth, not depth >32. A forged snapshot with depth 33 can pass. Reject invalid snapshots atomically, without changing an existing valid queue.
2. **Clock backlog:** `SimulationClock.advance()` limits executed ticks per call but retains the full excess accumulator. Test prolonged lag and repeated zero/short-delta advances. The fixed-timestep catch-up contract requires preventing unbounded catch-up; if the precise discard/debt policy is not approved, **present alternatives and ask the Owner rather than silently defining new timing semantics**. Do not hardcode a product tick rate.
3. **Event ordering / transaction boundary:** `TransactionEngine.execute()` processes newly generated due events ahead of pre-existing queued events. Verify whether this behavior is permitted by the approved `(scheduledTick, insertionSequence)` ordering **and** transaction atomicity contract. A causal chain is not automatically one atomic transaction. Construct tests where generated due events have later sequence but earlier/later scheduled ticks than existing due events. If an unavoidable semantic conflict remains, stop the affected fix and ask the Owner; do not silently redefine transaction membership or event order.
4. **Atomic failure coverage:** test handler exceptions, queue overflow during speculative execution, depth overflow during speculative execution, transaction >250, deferral with insufficient remaining budget, and malformed snapshot/inputs. Assert no partial mutation of state, queue, RNG, event IDs and insertion sequences on FAILED/DEFERRED; distinguish fail-stop metadata from canonical gameplay state.
5. **Identity/sequence integrity:** snapshot restore must reject duplicate IDs, duplicate/out-of-range insertion sequences, invalid counters, invalid tick/depth, and other malformed data relevant to the existing contract. Verify next event ID cannot collide with a restored ID and that next insertion sequence is preserved; do not change stable ID conventions without approval.
6. **Diagnostics:** assert code, tick, event ID, causal depth, queue size, checkpoint ID and recovery attempt on supported failures. When checkpoint data is unavailable, use explicit null; do not fabricate recovery attempts.
7. **Scheduler boundaries:** exactly 250 executed events/tick, 251st deferred; indivisible 2-event transaction with only 1 slot left; overdue FIFO precedence; generated events counted when actually executed, not when enqueued; no infinite retry within a tick.
8. **Deterministic replay:** compare full canonical snapshots and event order for identical inputs/seed across multiple ticks, including deferred and rollback paths. Ensure the test uses a deterministic test RNG and does not invent a production PRNG algorithm.
9. **Pause and input validation:** no tick advance during Pause, deterministic resume, invalid elapsed/tick/budget handling, bounded catch-up; preserve existing public API where possible.
10. **Existing regression safety:** ensure Game Factory/Phaser lifecycle, Hello Scene and other `@mfd/game` tests still pass.

## 4. Acceptance gates

- No malformed snapshot may restore an event with causal depth >32 or violate queue capacity 4096.
- Queue and transaction failure paths leave all live canonical state/counters unchanged before recovery.
- Event ordering remains deterministic and compatible with approved G06 contract; no hidden reordering of overdue events.
- Speculative transactions never commit >250 executed events in a tick; a transaction needing >250 triggers typed failure, while one exceeding only the **remaining** budget is deferred.
- Catch-up behavior is bounded under sustained lag **subject to Owner-approved debt/discard semantics**; do not claim full acceptance if unresolved.
- Diagnostics are complete and do not silently change gameplay state.
- All existing tests and typecheck pass, with new edge-case tests.
- No changes to `.agents/skills/`, unrelated game systems, Git history, or remote GitHub as part of Codex execution.
- Any unresolved contradiction is reported as a blocker, not guessed away.
